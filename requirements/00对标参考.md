# 00 · 对标参考表（抄同行最好的作业）

> `requirements/` 是**建站前的内容准备工作区**：把素材先准备在这里，再让 AI 照着产页。
> 本文件是两张准备表之一——**对标站结构拆解**。另一张是 [00事实来源.md](00事实来源.md)（事实来源清单）。
>
> 一句话：**同行就是最好的老师**。别人已经用真金白银的流量验证过什么结构能留住用户、广告位放哪能点得动——先拆解、再动手，避免埋头苦干。

## 怎么选对标站

选 **1-3 个流量好的同类型攻略站**（和你选的游戏同品类：都做 Roblox、都做网页小游戏……）：

- 大站：[Fandom](https://www.fandom.com) 的同品类站、[Mobalytics](https://mobalytics.gg) 级别的专业攻略站——验证过的天花板结构
- 独立站：搜你目标词排在第一页的个人站——**参考价值往往更高**，它的体量、预算和你一样，它能排上去的结构你能复制

## 拆解什么（四个维度，逐项记录）

1. **网站链接**：对标站 URL + 它排上去的目标词
2. **首页结构拆解**：导航怎么分（一级类目叫什么）、首屏放了什么模块（最新兑换码？热门攻略？）、广告位位置
3. **内页结构**：文章页的小节骨架（H2 顺序：直答→表格→FAQ？）、内链怎么互相引、有没有数据卡/交互组件
4. **广告位布局**：几个位、放在哪（首屏下/文末/侧栏/粘底）、什么样式——这直接决定你的广告收入天花板

## 模板（复制下面这段，每个对标站一份）

```markdown
## 对标站 1：{站名}

- **链接**：https://…
- **排上去的词**：{game} codes / {game} tier list（怎么确认：Google 搜这个词看它排第几）
- **首页结构**：
  - 导航：Codes / Guides / Tier Lists / …（按它的顺序抄录）
  - 首屏模块：置顶最新兑换码卡 + 热门 Boss 攻略 3 张卡
  - 广告位：首屏下方横幅 ×1、侧栏 ×1
- **内页结构**（拆它流量最高的一篇）：
  - H2 骨架：问题式标题 → 40 词直答 → 数据表格 → 分步骤 → FAQ
  - 内链：正文 3 条，指向自己的 codes 页和相邻 boss 页
  - 广告位：首个 H2 后 ×1、文末 ×1、移动端粘底 ×1
- **我要抄的**：<结构/模块上它做对了什么，例如"兑换码永远置顶首屏">
- **我要做得更好的**：<它的短板，例如"codes 一周没更新了，我日更">
```

## 怎么用

- 填完后，把本表连同 [00事实来源.md](00事实来源.md) 一起喂给 AI，再说"照这个结构给我做站/产页"——AI 有了具体参照，产出的结构不是凭空发明，是验证过的。
- 拆解结论直接映射到模板的配置层：它的导航分类 → `src/config/navigation.ts` 的类目设计（见 [docs/apply-template.md](../docs/apply-template.md)）；它的 H2 骨架 → 产页提示词的固定骨架（见 [docs/content-format.md](../docs/content-format.md)）；它的广告位布局 → 广告位开几个、开在哪（见 [docs/ads.md](../docs/ads.md)，时机原则同样参考）。

# Ball vs Ball 对标参考拆解（2026-09-29 建立）

## 对标站 1：games.gg

- **链接**：https://games.gg/roblox/ball-vs-ball-ultimate-tier-list/
- **排上去的词**：`ball vs ball tier list` / `ball vs ball best balls` / `ball vs ball guide`
- **页面形态与结构**：
  - 核心模块：完整的 42 种球分级（S 到 C），四维评价体系（Damage, Consistency, Counterplay, Mechanic）
  - 核心分类：球系家族（Ball, Explosion, Flyer）
  - 机制总结：指出 Rare 品质的球可能比 Legendary 更强（打破传统稀有度迷信）
- **我要抄的**：
  - 四维打分维度与球系家族分类，能极大地提升内容的专业度和玩家信任。
  - 突出实战性与反直觉结论（如 Spider Ball 与 Vampire Ball 在 Rare 中的逆天表现）。
- **我要做得更好的**：
  - games.gg 是综合站的二级长文，全篇拉通看很累；我们用 AnvilWiki 的卡片组件与清晰梯队（S/A/B/C）直观呈现。
  - games.gg 没有给单个热门球做独立的详细攻略页；我们为核心 S 级神球（Conductor, Laser, Vampire, Zone, Shackles）建立独立内页，全面接管高意向精准长尾词。

## 对标站 2：Pro Game Guides (PGG)

- **链接**：https://progameguides.com/roblox/ball-vs-ball-codes/
- **排上去的词**：`ball vs ball codes` / `ball vs ball roblox codes`
- **页面形态与结构**：
  - Codes 列表：文字罗列 Active Codes 和 Expired Codes
  - 步骤指引：How to redeem codes（带截图指引）
  - 获取更多码的渠道：Discord、Roblox Group
- **我要抄的**：
  - 极简的“代码 + 奖励 + 兑换方式”标准 3 步结构。
  - 明确提醒大小写敏感和末尾空格问题（解决玩家核心痛点）。
- **我要做得更好的**：
  - PGG 页面充斥着大量的插页广告与沉重的脚本，加载慢；AnvilWiki 纯静态极速秒开。
  - PGG 没有一键复制代码功能；AnvilWiki 自带一键复制与自动分区，跳出率更低。
  - 站内双向内链：PGG 的 codes 页只链接首页，我们的 codes 页直接内联 `ball-tier-list` 和 `beginner-guide`，互相传递权重。
